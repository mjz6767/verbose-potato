# Engineering Audit - 2026-09-04

## Scope and baseline

This audit covered the canonical Git repository and Unity project only. The initial tracked tree was clean at `7519e9198ac71ed71c90b3272b5352fb4f11ed42`, which matched `origin/main`; the product baseline is v2.23.0, campaign save schema v27, and Unity 6000.3.18f1. Migration recovery folders outside the canonical repository were not changed.

The current game has unusually strong deterministic coverage and a verified v2.23 package history. The highest-value gaps were at subsystem boundaries: settings were stored as campaign state, a responsive outer Party Setup panel still contained fixed-width controls, a required inventory smoke was not invoked by the build method, and a few malformed/pathological values could pass into runtime controllers.

## Improvements made

- Application preferences now use a dedicated, versioned `AshAndBrimstoneSettings.json`, written atomically with `.bak` recovery. Existing campaign fields remain readable, so save schema v27 does not change. App preferences override the copied campaign values after Continue.
- Party Setup now switches to a compact identity-control arrangement below the safe 1518-pixel breakpoint. Deterministic geometry checks cover 960x600 through 2048x1152 and both sides of the breakpoint.
- Save validation now rejects undefined modes, null combat collections/elements, duplicate unit IDs, invalid party links, undefined enum values, and combat payloads with no living unit. The loader can then try the backup rather than adopting a primary that will fail later.
- Combat movement rejects non-positive costs for a distinct destination and clamps reported budget/spend values. Exploration routing no longer proposes an adjacent route to inert blocking scenery.
- `BuildWindows` again runs `InventoryLootExperienceSmoke` as part of its in-process gate.
- RuleSmoke contracts cover preference round-trip/backup isolation, malformed-save fallback, movement edge cases, inert-object routing, compact Party Setup geometry, and matching help copy.
- Tooling guidance now reflects the existing original music/SFX library and the preferred extraction of deterministic rules from the large legacy partial class.
