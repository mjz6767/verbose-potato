# Astra project audit - 2026-09-05

## Scope

Audited the canonical Unity project at v2.23.0 / save schema 27, including the prior uncommitted audit changes. Three explicit `gpt-6-astra` reviews covered persistence, gameplay rules, and presentation/input; the coordinating pass reviewed verification and integrated the fixes. Baseline Git commit: `7519e9198ac71ed71c90b3272b5352fb4f11ed42`.

## Findings addressed

- **Campaign recovery could destroy its last healthy backup.** After loading a good backup beside a corrupt primary, the next save rotated corrupt data into the backup. Primary healing and protected backup rotation now cover both recovery and direct save. Older builds also preserve future-schema primary and backup files.
- **Name entry could launch a campaign.** Global shortcuts and Muster B/Return handling ran while editing the name field. Text editing and its submission frame now own those inputs; selected buttons retain native submission without duplicate Quick Start dispatch.
- **Pause content overlapped at supported sizes.** The settings area extended outside the 960x600 panel and crossed the status text; ordinary status copy also crossed New Game. Compact settings and separately reserved status bounds correct these overlaps.
- **Long Help pages were truncated.** A masked scrolling body, visible scrollbar, and keyboard paging keep the final paragraph reachable. Help owns modal input so background Tavern/Muster shortcuts cannot execute through it.
- **Life drain healed from overkill.** Drain and Soul Rend used computed damage even when the enemy had fewer hit points left. Healing now uses removed health while retaining each power's minimum and maximum-health cap; popups show actual recovery.
- **Buff removal was described as a cure.** Stealth consumption and shield/regeneration reductions no longer count toward cleared ailments. Harmful-effect cures and affected-unit reporting remain intact.
- **Verification was cumbersome and could misreport completion.** `Tools/InvokeProjectAudit.ps1` runs the existing gates through `ProjectAuditSmoke`, records a unique log, waits for the actual editor process, requires its exit and completion marker, and rejects caught-and-logged Unity errors. It does not create a Windows package.

The first launcher then waited for long-lived licensing descendants after the editor exited; the new runner waits on the editor process itself.

The runner observed no Unity Error/Exception/Assert messages during those checks. Log: `QA/project-audit/20260905-071821-bf28a039/unity.log`.

Controls and status copy fit, Help's final paragraph is reachable, and scrollbar positions agree with the visible content. Captures: `QA/project-audit/ui-review-2026-09-05/20260905-072202-836`. These verify rendered layout, not physical input or the final Windows player. The capture helper required a corrected import GUID and an explicit post-layout scrollbar rebuild for direct editor rendering; neither changed runtime behavior.

`git diff --check` and the PowerShell parser pass; all Unity asset GUIDs have valid 32-character form. [The evidence summary](ReleaseEvidence/audit-2026-09-05.json) retains the runtime-source fingerprint, log hashes, and eight PNG hashes while raw QA files remain local.
